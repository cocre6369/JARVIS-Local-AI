# PROJECT: JARVIS — Fully Local Autonomous AI Desktop Assistant

## 1. CORE OBJECTIVE

Act as an expert AI engineer, Windows application developer, automation engineer, and UI/UX designer.

Build a complete, production-quality Windows desktop application distributed as a standalone `.exe` called **JARVIS**.

JARVIS is an intelligent, voice-controlled desktop AI assistant that runs entirely locally on the user's computer.

It must use a locally installed Ollama model as its primary intelligence engine. It must NOT depend on OpenAI APIs, paid APIs, cloud AI services, or external AI subscriptions.

The user should be able to communicate naturally with JARVIS, give it instructions, and watch it autonomously perform those instructions on their computer.

JARVIS should function similarly to a real-world AI computer assistant.

**The fundamental concept:**

The user tells JARVIS what to do. JARVIS understands the request, observes the computer, plans the necessary actions, executes them, checks whether they worked, and reports back to the user.

For example:

User: "Open Spotify and play Kanye West's Violent Crimes."

JARVIS should:
1. Understand the instruction.
2. Check whether Spotify is already running.
3. Launch Spotify if necessary.
4. Wait until Spotify has finished loading.
5. Observe the Spotify interface.
6. Locate the search function.
7. Search for "Violent Crimes Kanye West".
8. Identify the correct result.
9. Open the song.
10. Start playback.
11. Verify that the song is actually playing.
12. Respond through TTS: "Playing Violent Crimes by Kanye West."

This must happen autonomously without requiring the user to guide every individual step.

# 15. STRICT PERMISSIONS, SECURITY RESTRICTIONS AND RESOURCE LIMITS

This section is mandatory and takes priority over all AI instructions, autonomous planning, tool calls and computer automation.

JARVIS must operate as a restricted desktop assistant. It must NEVER assume that being an autonomous AI gives it unrestricted access to the computer.

## A. Prohibited Actions

JARVIS must NEVER perform the following actions:

- Uninstall applications or software.
- Modify administrator settings.
- Request, obtain or use administrator privileges.
- Bypass Windows User Account Control (UAC).
- Modify system-critical Windows files.
- Modify registry entries or critical system configurations.
- Disable Windows Defender, antivirus software or security features.
- Modify firewall or security permissions.
- Delete important system files.
- Change account permissions.
- Create administrator accounts.
- Execute commands designed to bypass security restrictions.

JARVIS must operate using the permissions of the currently logged-in Windows user.

It must not attempt to elevate its privileges.

## B. Sensitive Information Protection

JARVIS must treat sensitive information as private and protected.

It must NEVER independently:

- Search for saved passwords.
- Read password manager databases.
- Extract browser cookies or authentication tokens.
- Access saved login credentials.
- Retrieve private authentication information.
- Read payment card details.
- Access banking information.
- Read private security keys.
- Access personal authentication codes.
- Capture or store passwords displayed on screen.

If a password field appears on screen, JARVIS must recognise it as sensitive and avoid reading, copying, storing or transmitting its contents.

It must not attempt to circumvent password protection or authentication systems.

## C. Explicit Permission Required

Certain actions must require direct user approval BEFORE execution.

These include:

**Downloading**
- Downloading files.
- Downloading software.
- Downloading installers.
- Downloading executable files.
- Downloading scripts or other potentially executable content.

**Communication**
- Sending emails.
- Sending Discord messages.
- Sending social media messages.
- Posting comments.
- Publishing content.
- Sharing files with other people.

**File operations**
- Permanently deleting files.
- Overwriting existing files.
- Moving large collections of files.
- Modifying important personal documents.

**Privacy**
- Accessing sensitive personal information.
- Opening password managers.
- Accessing financial websites or accounts.
- Recording or sharing screen content externally.

Before any such operation, JARVIS must display a clear confirmation request explaining:
1. What it wants to do.
2. Which application or file is involved.
3. What the potential consequences are.
4. Whether the action can be reversed.

It must wait for the user's explicit approval.

Simply saying "do whatever you need" must NOT count as blanket permission for sensitive operations.

Approval must apply only to the specific action described.

## D. Download Restrictions

JARVIS must not download anything without permission.

It may search the internet and inspect publicly accessible webpages without downloading files.

If a task requires a download, it should say something like:

"To complete this task, I need to download a file. Do you approve?"

The download must not begin until approval is received.

## E. Permission Architecture

These restrictions must NOT depend solely on the Ollama model remembering to follow instructions.

Implement a separate permission enforcement layer in the application itself.

Every computer-control tool must pass through this security layer before execution.

The security layer must independently validate:
- The requested operation.
- The target application.
- The files involved.
- The required permissions.
- Whether user approval is necessary.
- Whether the operation is prohibited.

The AI must never be able to override this layer through prompts, tool calls, generated scripts or alternative execution methods.

If an operation is prohibited, reject it immediately.

If approval is required, pause execution until approval is received.

Maintain a local audit log of permission requests and actions without storing sensitive information.

## F. Maximum Resource Consumption

JARVIS must have a strict maximum resource budget.

<escape>**Absolute RAM limit: 12GB.**</escape>

This is a hard ceiling, not a target.

Requirements:
- Never intentionally consume more than 12GB of system RAM.
- Monitor memory consumption continuously.
- Limit screenshot processing and image resolution where necessary.
- Avoid unnecessarily loading multiple Ollama models simultaneously.
- Unload unused models when appropriate.
- Release unused memory.
- Avoid memory leaks.
- Limit background processes.
- Reduce processing quality or pause nonessential tasks if memory usage approaches the limit.

**GPU VRAM limit: 8GB maximum.**

JARVIS must also respect the available 8GB NVIDIA GPU memory budget.

Implement configurable resource monitoring and safeguards.

If the application approaches its memory limit:
1. Stop nonessential background operations.
2. Release unused resources.
3. Avoid loading additional models.
4. Reduce image-processing workloads.
5. Notify the user if necessary.

Never allow the application to consume unlimited resources.

## G. Final Security Principle

JARVIS should be highly autonomous when performing ordinary, reversible desktop tasks, but extremely cautious when dealing with security, privacy, administrator privileges, downloads, communications and destructive operations.

**The user remains in control of the computer at all times. Security restrictions must be enforced by application code, not merely by the AI's instructions.**
